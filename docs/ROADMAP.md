# DomainAtlas Roadmap

本路线图描述产品能力的实现顺序，不替代具体 Issue。每个里程碑只保留目标、范围和验收条件。

状态说明：

- **Done**：已经完成；
- **Next**：当前优先级；
- **Planned**：后续计划；
- **Later**：暂不进入近期开发。

## M0：Agent 技术链路 — Done

目标：验证前后端流式对话和工具调用链路。

已完成：

- FastAPI 与 React Router 原型；
- `POST /agent` 流式接口；
- AI SDK 与 Pydantic-AI 消息转换；
- SSE 文本流和 Agent 消息转换；
- 基础校验、测试、Ruff 和 TypeScript 检查；
- 可运行的领域学习对话原型。

验收结果：用户可以通过前端描述学习目标并看到流式响应。

## M1：学习任务与框架确认 — Next

目标：把通用聊天入口替换为第一段真实学习工作流。

范围：

- 定义 `LearningBrief`；
- 创建学习任务；
- 处理主题歧义、范围过宽和时间不足；
- 生成 `FrameworkPlan`；
- 支持用户确认或修改计划；
- 保存任务阶段和结构化产物。

验收条件：

- 用户能够提交领域、背景、目标和时间预算；
- 系统返回有明确边界、模块和排除项的计划；
- 未确认计划前不能进入研究阶段；
- 结构化产物可以被重新读取。

## M2：研究、构建与发布 — Planned

目标：生成第一版带来源的 Atlas。

范围：

- 生成 `ResearchPack`；
- 保存来源、证据、争议和缺口；
- 生成 `AtlasDraft`；
- 执行确定性结构和引用校验；
- 生成 `QualityReport`；
- 发布不可变的 `AtlasVersion`。

验收条件：

- Atlas 中的关键结论能够定位到来源；
- 模块、节点和关系满足 schema；
- 未通过硬性校验的草稿不能发布；
- 发布版本可以稳定重现和读取。

## M3：Atlas 工作区与学习路径 — Planned

目标：让用户能够浏览和学习，而不只是查看生成结果。

范围：

- 领域总览；
- 模块与节点详情；
- 概念关系；
- 来源与证据视图；
- 推荐学习路径；
- 节点学习状态。

验收条件：

- 用户可以从总览进入节点和来源；
- 不同视图引用相同的知识对象；
- 学习进度可以映射到具体节点。

## M4：自测、薄弱点与局部扩展 — Later

目标：形成最小学习反馈闭环。

范围：

- 结构性自测；
- `AssessmentResult`；
- 薄弱节点和关系定位；
- 针对薄弱点的复习任务；
- 有边界的局部扩展。

验收条件：

- 自测结果不仅记录分数，还能定位知识缺口；
- 扩展任务必须具有预算、范围和父节点；
- 新内容不会静默修改已发布版本。

## 横向工程能力

以下能力按需要进入对应里程碑，不单独驱动产品开发：

- PostgreSQL 持久化；
- 后台任务恢复；
- 预算和模型调用控制；
- 认证与多用户；
- 限流、日志、监控和部署；
- 数据迁移与版本兼容。

## 当前最小演示目标

```text
创建任务
→ 确认 FrameworkPlan
→ 生成结构化 Atlas
→ 浏览节点与来源
→ 完成一次自测
```

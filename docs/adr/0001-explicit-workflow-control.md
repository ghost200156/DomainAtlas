# ADR-0001：使用显式工作流控制学习阶段

- 状态：已接受
- 日期：2026-07-14

## 背景

DomainAtlas 需要依次完成范围校准、框架确认、研究、Atlas 构建、校验和发布。若只依赖 Agent 从聊天记录推断当前阶段，任务恢复、重试、预算控制和发布约束都会变得不可靠。

## 决策

由显式 Python 工作流维护任务阶段、结构化产物、重试和发布条件。Agent 只负责有边界的规划、研究、构建和审查步骤，不作为业务状态的唯一来源。

工作流至少区分以下状态：

```text
draft
→ awaiting_plan_confirmation
→ researching
→ building
→ reviewing
→ published
→ failed
```

## 影响

- 阶段转换可以被测试、持久化和恢复；
- 用户确认、预算限制和发布校验可以成为硬性条件；
- Agent 提示词与工作流编排需要分别维护；
- 通用聊天入口仍保留为独立原型；第一版主流程已经改用显式任务 API。

## 当前实现备注

第一版 Demo 已通过 `DemoOrchestrator`、`DemoRun` 和任务 API 落实该决策。当前后台任务仍运行在 FastAPI 进程内，服务重启后不能自动恢复；这属于生产化缺口，不改变“工作流状态不由 Agent 对话维护”的决策。

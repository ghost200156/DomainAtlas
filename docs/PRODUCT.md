# DomainAtlas 产品定义

## 产品定位

DomainAtlas 是一个知识地图式的领域学习 Agent，帮助用户在有限时间内进入陌生领域，形成第一版**有边界、有结构、有来源、可探索、可验证**的认知框架。

它不是通用问答工具，也不是一次性长报告生成器。它试图补充搜索、普通问答和固定课程之间缺失的一层：把零散信息组织成可以持续学习、核查和扩展的知识结构。

## 用户应获得什么

完成一次学习任务后，用户应能够：

- 用自己的话解释领域定义和边界；
- 说出关键概念并解释它们的关系；
- 说明至少一条核心机制；
- 比较主要路径、案例或争议；
- 区分事实、推断、争议和未知问题；
- 找到关键结论的来源；
- 明确下一步应该学习什么。

## 核心对象：Atlas

`Atlas` 不是一次性报告，而是由同一份知识模型投影出的多个学习视图：

```text
Atlas
├── 领域总览与边界
├── 模块、概念与关系
├── 核心问题与机制
├── 案例、时间线与争议
├── 来源与证据
├── 学习路径
└── 自测题与学习进度
```

所有视图引用同一组知识对象，避免概念图、时间线、来源和学习内容分别生成后互相矛盾。

## 目标学习闭环

```text
创建任务
→ 校准范围
→ 确认学习框架
→ 研究和整理证据
→ 构建并检查 Atlas
→ 按地图或路径学习
→ 自测并定位薄弱点
→ 复习或局部扩展
```

第一版 Demo 当前使用的结构化产物包括：

- `LearningBrief`：学习目标、背景、成果和时间预算；
- `FrameworkPlan`：模块、核心问题、重点和排除项；
- `ResearchPack`：来源、证据、争议和信息缺口；
- `AtlasDocument`：模块、概念、关系、机制、案例、来源、学习路径和自测；
- `QualityReport`：结构、引用和覆盖质量；
- `AssessmentFeedback`：自测得分、反馈及其对应的复习节点。

未来产品计划在 `AtlasDocument` 之外引入可修订的 `AtlasDraft` 和不可变的 `AtlasVersion`。它们尚未在第一版 Demo 中实现，不应与当前 JSON 任务存储混淆。

## 产品边界

初版不计划支持：

- 通用聊天或即时事实查询；
- 只生成长文、报告或演示文稿；
- 承诺快速精通一个专业领域；
- 无预算、无边界地自动扩展知识地图；
- 教师后台、课程市场、社区和多人协作；
- 实时行业监控；
- 医疗、法律和投资等高风险决策建议。

当前未实现的生产能力，例如认证、多用户、持久化、限流和监控，属于工程路线图，而不是永久产品边界。
